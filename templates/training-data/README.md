# Training data template

[`pix-training-example-v2.csv`](pix-training-example-v2.csv) is a spreadsheet template for training data: one row per past Pix payment, with the scoring input that existed when the payment was decided and the outcome observed later. Its rows are synthetic examples; replace them with your own records. The layout is specified in [`pix-training-csv-v1`](../../docs/contracts/pix-training-csv-v1.md).

## Workflow

Keep filled files in `data/`, which git ignores, so real payment data is never committed:

```bash
mkdir -p data
cp templates/training-data/pix-training-example-v2.csv data/training.csv
# fill data/training.csv in a spreadsheet, then export it as CSV
go run ./cmd/convert -input data/training.csv -output data/training.jsonl
go run ./cmd/train -config docs/contracts/training-config-examples/01-baseline.json \
  -dataset data/training.jsonl -run-dir data/run
```

`convert` validates every row as `train` would and writes the JSON Lines dataset only when every row is valid. It reports each problem with the row of the file, counting the header as row 1, and the column. Spreadsheets in Brazilian Portuguese usually separate cells with semicolons: convert them with `-separator ';'`. Choose the configuration's `train_end` and `validation_end` so every partition of your data has fraud and legitimate records with mature labels.

## Rules

- **One column per field.** Every column must be present, in any order; no other column is allowed. `training_example_version` and `contract_version` are implied.
- **Empty means null.** An empty cell is `null`: missing information, never zero. Write `0` only when the value is a known zero.
- **Observations need their `as_of`.** An observation exists only when its `as_of` is filled. With an empty `as_of`, it is missing, and every other column of it must be empty.
- **Subjects that do not apply stay empty.** With `pix_payment.payer_device_usage` `no_payer_device`, every `observations.payer_device.` column must be empty; with `pix_payment.recipient_key_usage` `no_pix_key`, every `observations.recipient_pix_key.` column; with `pix_payment.payer_limit_period` `no_period_limit`, every `observations.payer_account.period_limit.` column.
- **Counters.** A DICT counter whose `d90`, `m12`, and `m60` are all empty is missing as a whole.
- **Point in time.** Every value must be what your systems knew at `decision_time`, with a true `as_of`. A value filled in later leaks the future into training, and the toolkit cannot detect it.
- **No personal data.** `group_key` is a pseudonymous key you choose; never use a CPF, CNPJ, account number, or name.
